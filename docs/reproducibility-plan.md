# Reproducibility plan

## Scope

This document defines the minimum evidence required for the future software to support the manuscript. It does not claim that the draft results have already been reproduced.

## Data contract

- Verify raw-file SHA-256 hashes before processing.
- Preserve `data/raw/` as immutable input.
- Record row counts before and after every exclusion.
- Define unknown-value handling per column.
- Aggregate diagnosis codes using a versioned, tested mapping.
- Define prediction-time availability for every candidate feature.
- Fit all learned preprocessing inside each training split.
- Decide and document encounter-level versus patient-grouped splitting.

## Experiment contract

Every run should record:

- source revision and dirty-worktree status;
- dataset hashes;
- random seeds and exact split membership;
- candidate feature list and target subset size;
- relevance and redundancy estimators;
- QUBO coefficients, scaling and constant offset;
- optimizer, budget, stopping criteria and sampled bitstrings;
- QAOA depth, shots, backend, transpilation seed and noise/hardware metadata;
- downstream model and hyperparameters;
- wall-clock time and environment/package versions.

## Required verification

1. Unit-test target mapping, diagnosis aggregation and exclusions.
2. Compare QUBO matrix energy with a direct objective calculation on known bitstrings.
3. Verify the Ising conversion preserves ordering up to the documented constant/scale.
4. Exhaustively solve small instances and compare QAOA/classical solver outputs.
5. Assert exact or explicitly tolerated cardinality behavior.
6. Confirm no preprocessing or feature scoring sees validation/test data.
7. Recompute every reported table from machine-readable result files.

## Evaluation

Use identical outer splits for all selection methods. Report AUC, balanced accuracy, F1, precision, recall and specificity with uncertainty across splits. Also report subset size, average pairwise redundancy and a clearly defined stability index. Threshold selection, if used, must occur without access to the final test fold.

The full candidate model, mutual-information top-k, LASSO selection and simulated annealing on the identical QUBO are required comparators. Quantum results should be separated into ideal simulation, noisy simulation and physical-QPU execution when applicable.

## Claims policy

Do not describe quantum advantage unless supported by a predeclared, like-for-like resource comparison and statistically defensible evidence. Hardware compatibility alone is not evidence of execution on hardware. All manuscript values remain provisional until generated by the checked-in pipeline.
